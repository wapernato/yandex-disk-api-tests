# Результаты проверки

Дата: **5 октября 2026**, часовой пояс Europe/Moscow. Локальное окружение: macOS ARM64, OpenJDK 17.0.20.1 (Temurin), Maven 3.9.11, JUnit 5.11.4, REST Assured 5.5.1.

## Успешный запуск

Запущены компиляция всех тестовых классов и проверки через Maven, затем через поставляемый `./mvnw -Pauth verify`. В проверяющем окружении `JAVA_HOME` указывал на JDK 17, а Maven использовал временный локальный кэш. Это не требуется менять в исходниках.

| Класс | Выполнено | Failures | Errors | Skipped |

| `TestConfigTest` | 7 | 0 | 0 | 0 |
| `DiskClientTest` | 9 | 0 | 0 | 0 |
| `PollerTest` | 5 | 0 | 0 | 0 |
| `OperationAwaiterTest` | 10 | 0 | 0 | 0 |
| `TestNamespaceTest` | 6 | 0 | 0 | 0 |
| `AuthorizationIT` | 8 | 0 | 0 | 0 |
| **Итого** | **45** | **0** | **0** | **0** |

`AuthorizationIT` отправлял реальные запросы к `https://cloud-api.yandex.net`: GET metadata, PUT create folder, POST copy и DELETE resource; каждый метод проверялся без токена и с заведомо невалидным токеном. Все восемь ответов имели HTTP 401 и JSON-поля `error`, `message`, `description`. Валидные учётные данные не использовались.

Локальные тесты проверили передачу OAuth и URL-кодирование через настоящий HTTP-сервер на loopback, отсутствие Authorization при пустом токене, защиту ссылок операций, отказ от небезопасных путей удаления, состояния success/in-progress/failed, неизвестные состояния, таймаут, interruption и настройку окружения.

Maven Wrapper скачал Maven из Maven Central и успешно проверил SHA-256. Дистрибутив отдельно проверен по опубликованной SHA-512. В скрипте Wrapper 3.3.2 внесена одна поправка совместимости: `sha256sum -c -` явно читает контрольную сумму из stdin и работает с BSD/macOS и GNU/Linux. Версия и лицензирующие заголовки Wrapper сохранены.

## Ограничения

**20 сценариев `DiskResourcesIT` с валидным OAuth не выполнены:** в окружении не было `YANDEX_DISK_TOKEN` отдельного тестового аккаунта. Эти классы успешно скомпилированы; позитивные операции, ошибки с валидной авторизацией, реальное получение 202, реальная очистка и фактические статусы операций не подтверждены интеграционным прогоном. Локальные проверки механизма ожидания не заменяют такую проверку.

Отдельно выполнен `./mvnw -Plive -Dit.test=DiskResourcesIT verify` без токена. Ожидаемый результат — **BUILD FAILURE** в `@BeforeAll` с сообщением `Set YANDEX_DISK_TOKEN from a dedicated Yandex test account.` До создания данных выполнение не дошло. Это проверка явного отказа при неверной настройке; она не считается успешным интеграционным прогоном.

GitHub Actions настроен в `.github/workflows/tests.yml`. Этот документ фиксирует локальный запуск, а не обещает результат будущих CI-запусков. Windows и другие версии JDK отдельно не проверялись.

Для завершения проверки подготовьте отдельный Яндекс ID и токен по README, затем выполните `./mvnw -Plive verify`. После фактического успешного прогона обновите этот отчёт результатами из Failsafe.
